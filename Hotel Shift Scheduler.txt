版本: 1.0

用途: 供 opencode 逐階段實作開發使用

================================================================================
一、專案概述
================================================================================

目標:
  開發一個飯店排班應用程式，負責排定 A/B/C 班次，D 班（大夜）由另一館
  負責人排定後手動輸入。系統依據排班規則自動求解最佳班表。

部署需求:
  - Portable / Standalone：單一資料夾，不需安裝
  - 目標環境：Windows 10 / 11 (x64)
  - 雙擊 .exe 啟動 → 自動開啟瀏覽器 → localhost 使用
  - 資料儲存在資料夾內的 SQLite 檔案
  - 整個資料夾可複製到任何 Windows 10/11 機器直接使用

技術棧:
  Backend : Python 3.11 + FastAPI + OR-Tools (CP-SAT Solver)
  Frontend: React 18 + TypeScript + Vite + Tailwind CSS + shadcn/ui
  Database: SQLite (檔案式，隨資料夾攜帶)
  State   : Zustand
  HTTP    : TanStack Query (React Query)
  打包    : PyInstaller (Backend → .exe) + Vite build (Frontend → static)

二、班次定義
================================================================================

班次    時間             每日人數    性質
------  ---------------  --------    --------------------------------
A       07:30 - 15:30    1~2 人      早班，每天必須有人
B       11:30 - 19:30    0~1 人      中班，非必需
C       15:30 - 23:30    1~2 人      晚班，每天必須有人
D       23:30 - 07:30    0~1 人      大夜班，手動輸入為主

說明:
  - 24 小時營業，A+C 涵蓋 07:30-23:30，D 班涵蓋 23:30-07:30
  - D 班不在本系統的自動排班責任範圍
  - D 班由另一館負責人排班，Josh 手動輸入到系統
  - 當大夜專職人員不足時，另一館會回報哪天缺 D 班，
    由 Josh 系統中的 C+D 備援人員補上

================================================================================
三、員工角色分類
================================================================================

角色            排班方式      可上班班次      預設偏好    說明
------------    ----------    -----------    --------    ---------------------
一般員工        自動排班      A / B / C       使用者設定  主要排班對象
大夜專職        手動輸入      D 為主          D           在系統內顯示，
                                                          D 班由另一館排定
                                                          後手動 Key 入
C+D 備援        自動排班      C 為主, D 備援  C           平常排 C 班；
                                                          收到缺 D 指示時
                                                          改排 D 班，C 班
                                                          由系統找人遞補

D 班備援觸發流程:
  1. 另一館負責人排 3 位大夜專職的 D 班
  2. 大夜不足時，回報「某日缺 D」
  3. Josh 在系統標記該日為「D 班備援日」
  4. C+D 備援人員當日改排 D 班（非 C 班）
  5. 系統自動找人遞補當日 C 班
  6. 若無人可遞補 C 班 → 排班失敗，回報錯誤

角色預設值（可在 UI 調整）:
  一般員工   → available_shifts = ["A","B","C"], preferred_shift = null
  大夜專職   → available_shifts = ["D"],         preferred_shift = "D"
  C+D 備援  → available_shifts = ["C","D"],      preferred_shift = "C"

四、排班規則 — 硬性約束（13 條，必須滿足）
================================================================================

H1  每日班次覆蓋
    每天至少 1 人 A 班、至少 1 人 C 班。
    B 班 0~1 人，D 班 0~1 人，A/C 班各最多 2 人。

H2  每週休 2 天
    週一至週日為一週。
    每人每週一般休假恰好 2 天。
    跨月不重置（如 7/27~8/2 為同一週，7 月已休 2 天則 8/1 不可再休）。
    特休不計入此 2 天。
    不完整週（月初/月末 < 5 天）最多休 2 天。

H3  週末休假限制
    一般/C+D備援/管理職：每人每月週六與週日休假加總恰好 2 天。
    大夜專職：維持最多 2 天（<=2，因跑館僅見本館部分排班）。
    特休不受此限制。

H4  連續上班上限
    每人最多連續上班 5 天。
    任意連續 6 天至少 1 天休或特休。
    特休可中斷連續上班天數累計。

H5  班次銜接禁止（硬性）
    以下銜接禁止，中間至少須隔 1 天休假或特休：
      C → A  禁止
      D → A  絕對禁止
      D → C  禁止

H6  指定休假
    每人每月最多 2 天指定休假，可選 0~2 天，可不指定。
    指定休假當天必須排為休假。

H7  可用班次限制
    只能安排員工勾選的可上班班次（available_shifts）。

H8  跨月班次銜接
    載入上月最後 5 天排班資料。
    確保本月第 1 天不違反班次銜接規則（H5）。
    確保本月開頭不違反連續上班上限（H4）。

H9  跨月週連續性
    每週休 2 天的計算不因月份切換而重置。
    跨月週的休假天數須合併計算。

H10 一人一天一班
    每人每天最多排 1 個班次（含休假/特休）。

H11 D 班備援邏輯
    標記為 D 班備援日的當天：
      - C+D 備援人員改排 D 班
      - 原本該人員的 C 班由系統自動找人遞補
      - 若無人可遞補 C 班 → 排班失敗，回報錯誤

H12 連休 2 日限制
    每人每月 1~2 次「連續 ≥2 天休假」。
    判定規則：
      - 一般休假（自動排程）→ 參與連休計算
      - 指定休假             → 參與連休計算
      - 特休                 → 不參與，且會打斷連續判定
    連續 3 天以上休假仍算 1 次（不常出現）。
    特休不計入且會打斷連休判定（如 8/5 休 + 8/6 特休 → 不算連休）。
    每月累計 1~2 次。

H13 大夜專職手動輸入
    大夜專職人員的 D 班由手動輸入。
    系統驗證大夜人員的休假規則合規
    （每週休 2 天、連續上班上限、連休 2 日限制等同樣適用）。

================================================================================
五、排班規則 — 軟性約束（9 條，盡量滿足，影響最佳化目標）
================================================================================

S1  避免連續 5 天上班
    盡量不要排到連續 5 天上班。

S2  B→A 盡量避免
    B 班隔天盡量不接 A 班。

S3  C→B 盡量避免
    C 班隔天盡量不接 B 班。

S5  偏好班次
    盡量滿足員工設定的偏好班次。

S6  公平分配
    盡量均衡各員工的總上班天數（最大最小值差最小化）。

S7  D 班備援最小化
    盡量讓 C+D 備援人員上 C 班而非 D 班。

S8  管理職備援最小化
    盡量讓管理職上 M 班，而非 A/B/C/D 班。

S9  連休 2 次優先
    盡量讓每人每月達成 2 次連休（配合 H12 的 1~2 次範圍）。

S10 週末人力加強
    週五/週六盡量加人，優先序雙 A = 雙 C = M > B；
    平日（週日~週四）優先排 B（v1.1.1-beta 調整）。

===============================================================================
六、班次銜接矩陣
================================================================================

前日↓ ＼ 今日→    A       B       C       D       一般休    特休
---------------  ------  ------  ------  ------  -------   ------
A                 ✅      ✅      ✅      —       ✅        ✅
B                 ⚠️(S2)   ✅      ✅      —       ✅        ✅
C                 ❌(H5)  ⚠️(S3)   ✅      ✅       ✅        ✅
D                 ❌(H5)   ✅     ❌(H5)   ✅      ✅        ✅
一般休             ✅      ✅      ✅      ✅      ✅        ✅
特休               ✅      ✅      ✅      ✅      ✅        ✅

✅ = 允許
⚠️ = 盡量避免（軟性約束）
❌ = 禁止（硬性約束，至少隔 1 天休/特休）
— = 基本不會出現（因 D 班排班邏輯，A→D 和 B→D 不會發生）

================================================================================
七、特休（年假）規則
================================================================================

特休不受以下限制：
  - 每月指定休假 2 天額度（特休不佔用）
  - 每週休 2 天限制（特休不計入）
  - 週末休假限制（特休可休週六/週日）
  - 連休 2 日限制（特休不參與且會打斷連休判定）

特休受以下限制：
  - 連續上班上限（特休算休假，可中斷連續上班天數累計）

特休使用：
  - 可任意天數、任意日期使用
  - 排班表中與一般休假視覺區分（特休 = 紫色，一般休 = 紅色）

================================================================================
八、連休 2 日判定邏輯
================================================================================

參與連休計算的休假類型:
  一般休假（自動排程）  → 參與 ✅
  指定休假              → 參與 ✅
  特休                  → 不參與 ❌（且打斷連休判定）

判定規則:
  - 連續 ≥2 天的「參與型休假」段 → 算 1 次
  - 連續 3 天以上 → 仍算 1 次
  - 每月累計 1~2 次
  - 特休會打斷連續判定（特休那天不算，且前後分開計算）

範例:
  8/5(休) 8/6(休)                         → 1 次連休 ✅
  8/5(休) 8/6(休) 8/20(休) 8/21(休)       → 2 次 ✅（已達上限）
  上述 + 8/28(休) 8/29(休)                → 3 次 ❌ 超過限制
  8/5(休) 8/6(特休)                       → 不算連休 ✅（特休打斷）
  8/5(休) 8/6(休) 8/7(特休)               → 8/5-8/6 算 1 次；8/7 不影響
  8/5(休) 8/6(休) 8/7(休)                 → 連續 3 天，算 1 次
  8/5(指定休) 8/6(指定休)                 → 算 1 次連休

跨月連休判定:
  按月歸屬計算。如 7/30(休) 7/31(休) 8/1(休) 8/2(休)：
  → 7 月算 1 次（7/30-7/31）
  → 8 月算 1 次（8/1-8/2）
  → 合計 2 次，各月分別計算

================================================================================
九、跨月銜接機制
================================================================================

需要載入上月最後 5 天的排班資料，用於驗證三件事:

1. 班次銜接
   上月最後一天的班次 → 本月第一天，須符合銜接矩陣。
   例: 7/31 為 C 班 → 8/1 不可為 A 班。

2. 連續上班天數
   上月最後 N 天若連續上班，本月開頭繼續累計，不得超過 5 天。
   例: 7/29(休) 7/30(B) 7/31(C) → 8/1 可上班（已連續 2 天）
       7/27(A) 7/28(B) 7/29(C) 7/30(A) 7/31(B) → 8/1 必須休（已連續 5 天）

3. 跨月週休假
   跨月週的休假天數合併計算，不因月份切換重置。
   例: 7/27(一)~8/2(日) 為同一週，7 月已休 2 天 → 8/1~8/2 不可再休。

4. 跨月連休
   按月歸屬計算（見上方「跨月連休判定」）。

資料來源:
  (a) 自動讀取上月排班結果（若系統中有上月資料）
  (b) 手動輸入上月最後 5 天班次（首次使用或無上月資料時）

十、資料庫 Schema (SQLite)
================================================================================

----------------------------------------
TABLE: employees
----------------------------------------
  id                  INTEGER PRIMARY KEY AUTOINCREMENT
  name                TEXT NOT NULL
  role                TEXT NOT NULL  -- 'general' | 'night' | 'cd_backup'
  available_shifts    TEXT NOT NULL  -- JSON array, e.g. '["A","B","C"]'
  preferred_shift     TEXT           -- 'A' | 'B' | 'C' | 'D' | NULL
  scheduling_mode     TEXT NOT NULL  -- 'auto' | 'manual'
  is_active           INTEGER NOT NULL DEFAULT 1
  created_at          TEXT NOT NULL  -- ISO datetime
  updated_at          TEXT NOT NULL  -- ISO datetime

  INDEX: idx_employee_name (name)
  INDEX: idx_employee_role (role)

----------------------------------------
TABLE: schedule_entries
----------------------------------------
  id                  INTEGER PRIMARY KEY AUTOINCREMENT
  employee_id         INTEGER NOT NULL REFERENCES employees(id) ON DELETE CASCADE
  year                INTEGER NOT NULL
  month               INTEGER NOT NULL
  day                 INTEGER NOT NULL
  shift               TEXT NOT NULL  -- 'A' | 'B' | 'C' | 'D' | 'OFF' | 'SPECIAL'
  source              TEXT NOT NULL  -- 'auto' | 'manual' | 'night_input' |
                                      -- 'backup' | 'designated' | 'special'
  created_at          TEXT NOT NULL
  updated_at          TEXT NOT NULL

  UNIQUE: (employee_id, year, month, day)
  INDEX: idx_schedule_ym (year, month)
  INDEX: idx_schedule_emp_ym (employee_id, year, month)

----------------------------------------
TABLE: designated_off_days
----------------------------------------
  id                  INTEGER PRIMARY KEY AUTOINCREMENT
  employee_id         INTEGER NOT NULL REFERENCES employees(id) ON DELETE CASCADE
  year                INTEGER NOT NULL
  month               INTEGER NOT NULL
  day                 INTEGER NOT NULL
  created_at          TEXT NOT NULL

  UNIQUE: (employee_id, year, month, day)
  INDEX: idx_designated_ym (year, month)

  -- 每人每月最多 2 天（應用層驗證）

----------------------------------------
TABLE: special_leaves
----------------------------------------
  id                  INTEGER PRIMARY KEY AUTOINCREMENT
  employee_id         INTEGER NOT NULL REFERENCES employees(id) ON DELETE CASCADE
  year                INTEGER NOT NULL
  month               INTEGER NOT NULL
  day                 INTEGER NOT NULL
  created_at          TEXT NOT NULL

  UNIQUE: (employee_id, year, month, day)
  INDEX: idx_special_ym (year, month)

  -- 無天數限制

----------------------------------------
TABLE: d_backup_requests
----------------------------------------
  id                  INTEGER PRIMARY KEY AUTOINCREMENT
  year                INTEGER NOT NULL
  month               INTEGER NOT NULL
  day                 INTEGER NOT NULL
  assigned_employee_id INTEGER REFERENCES employees(id)  -- NULL = 未指派
  status              TEXT NOT NULL DEFAULT 'pending'  -- 'pending' | 'assigned' | 'failed'
  note                TEXT
  created_at          TEXT NOT NULL

  UNIQUE: (year, month, day)
  INDEX: idx_backup_ym (year, month)

----------------------------------------
TABLE: previous_month_links
----------------------------------------
  id                  INTEGER PRIMARY KEY AUTOINCREMENT
  employee_id         INTEGER NOT NULL REFERENCES employees(id) ON DELETE CASCADE
  year                INTEGER NOT NULL   -- 目標月份（即本月）
  month               INTEGER NOT NULL   -- 目標月份（即本月）
  day_5_shift         TEXT  -- 上月倒數第 5 天班次
  day_4_shift         TEXT  -- 上月倒數第 4 天班次
  day_3_shift         TEXT  -- 上月倒數第 3 天班次
  day_2_shift         TEXT  -- 上月倒數第 2 天班次
  day_1_shift         TEXT  -- 上月最後 1 天班次
  source              TEXT NOT NULL DEFAULT 'auto'  -- 'auto' | 'manual'
  created_at          TEXT NOT NULL

  UNIQUE: (employee_id, year, month)

================================================================================
十三、排班引擎核心設計
================================================================================

----------------------------------------
求解流程
----------------------------------------
1. 載入資料
   - 員工列表（含角色、可用班次、偏好）
   - 指定休假 + 特休
   - 跨月銜接（上月最後 5 天）
   - 大夜班表（手動輸入，固定不變）
   - D 班備援指示

2. 前處理
   - 計算每週分組（含跨月週）
   - 識別週六/週日
   - 標記 D 備援日 → C+D 備援人員強制排 D
   - 計算跨月週已休天數
   - 固定大夜專職人員的班次（手動輸入值）
   - 固定指定休假與特休的格位

3. 建構 CP-SAT 模型
   - 決策變數: x[emp, day, shift] ∈ {0, 1}
   - 13 條硬性約束
   - 9 條軟性約束 → 目標函數

4. 求解
   - CP-SAT Solver
   - 逾時 30 秒（可調）
   - 8 worker 平行

5. 後處理
   - 提取排班結果
   - 統計報表
   - 規則驗證報告
   - 儲存至資料庫

----------------------------------------
決策變數
----------------------------------------
  x[e, d, s] = 1  若員工 e 在第 d 天上 s 班
  e ∈ {0, ..., num_employees - 1}
  d ∈ {0, ..., num_days - 1}
  s ∈ {A, B, C, D, OFF, SPECIAL}

  對於大夜專職人員：班次固定為手動輸入值，不設決策變數
  對於指定休假/特休日：班次固定，不設決策變數
  對於 D 備援日的 C+D 備援人員：固定為 D 班，不設決策變數

----------------------------------------
硬性約束實作對照
----------------------------------------
H1  每日覆蓋:
    for each day d:
      sum(x[e,d,A] for e) >= 1
      sum(x[e,d,A] for e) <= 2
      sum(x[e,d,C] for e) >= 1
      sum(x[e,d,C] for e) <= 2
      sum(x[e,d,B] for e) <= 1
      sum(x[e,d,D] for e) <= 1

H2  每週休2天:
    for each emp e, for each week w:
      if len(w) >= 5:
        sum(x[e,d,OFF] for d in w) == 2
      else:
        sum(x[e,d,OFF] for d in w) <= 2
    (特休不計入 OFF；OFF = 一般休假 + 指定休假)

H3  週末限制:
    for each emp e:
      非大夜: sum(x[e,d,OFF] for d in saturdays) + sum(x[e,d,OFF] for d in sundays) == 2
      大夜專職: sum(x[e,d,OFF] for d in saturdays) + sum(x[e,d,OFF] for d in sundays) <= 2

H4  連續上班上限:
    for each emp e, for d in 0..num_days-6:
      sum(x[e,d+i,OFF or SPECIAL] for i in 0..5) >= 1
    (含跨月：上月最後 5 天的連續上班天數須一起計算)

H5  班次銜接禁止:
    for each emp e, for d in 0..num_days-2:
      x[e,d,C] + x[e,d+1,A] <= 1    (C→A 禁止)
      x[e,d,D] + x[e,d+1,A] <= 1    (D→A 禁止)
      x[e,d,D] + x[e,d+1,C] <= 1    (D→C 禁止)
    (含跨月：上月最後一天 → 本月第一天)

H6  指定休假:
    for each emp e, for each designated day d:
      x[e,d,OFF] == 1

H7  可用班次:
    for each emp e, for each day d, for s not in e.available_shifts:
      x[e,d,s] == 0

H8  跨月班次銜接:
    上月最後一天班次 → 本月第一天，套用 H5 銜接規則

H9  跨月週連續性:
    跨月週的 OFF 天數合併計算（上月部分 + 本月部分 = 該週總休假）
    若上月部分已休 2 天 → 本月部分不可再休

H10 一天一班:
    for each emp e, for each day d:
      sum(x[e,d,s] for s in ALL_SHIFTS) == 1

H11 D班備援:
    for each D backup day d:
      cd_backup_employee 的 x[e,d,D] == 1 (固定)
      sum(x[other_e,d,C] for other_e) >= 1 (確保 C 班有人)

H12 連休2日限制:
    for each emp e:
      1 <= 連續 ≥2 天 OFF 的段數 <= 2
      (特休不計入，且打斷連續判定)

H13 大夜專職手動:
    大夜專職人員的班次固定為手動輸入值
    同樣驗證 H2/H3/H4/H12 等規則

----------------------------------------
軟性約束 → 目標函數
----------------------------------------
最大化以下加總:

  S1 避免連續5天 (權重 -10):
    for each emp e, for d in 0..num_days-5:
      is_five = (sum(work for 5 consecutive days) == 5)
      objective += is_five * (-10)

  S2 B→A避免 (權重 -5):
    for each emp e, for d in 0..num_days-2:
      objective += x[e,d,B] * x[e,d+1,A] * (-5)
    (需線性化：引入輔助布林變數)

  S3 C→B避免 (權重 -5):
    for each emp e, for d in 0..num_days-2:
      objective += x[e,d,C] * x[e,d+1,B] * (-5)

  S5 偏好班次 (權重 +5):
    for each emp e with preferred_shift p, for each day d:
      objective += x[e,d,p] * 5

  S6 公平分配 (權重 -3):
    max_work = max(total_work_days across employees)
    min_work = min(total_work_days across employees)
    objective += (max_work - min_work) * (-3)

  S7 D班備援最小化 (權重 -2):
    for each cd_backup emp e, for each day d:
      objective += x[e,d,D] * (-2)
    (非備援日的 D 班額外懲罰)

  S8 管理職備援最小化 (權重 -15):
    for each manager e, for each day d, for s in A/B/C/D:
      objective += x[e,d,s] * (-15)

  S9 連休 2 次優先 (權重 +8):
    for each emp e:
      objective += (連休次數) * 8

  S10 週末人力加強 (權重 雙A +6 / 雙C +6 / M +6 / 平日B +3):
    for each 週五/週六 d:
      若 sum(x[e,d,A]) == 2 → +6；若 sum(x[e,d,C]) == 2 → +6
      objective += sum(x[e,d,M]) * 6
    for each 週日~週四 d:
      objective += sum(x[e,d,B]) * 3

import os
import sys
import webbrowser
import threading
import uvicorn

def open_browser():
    import time
    time.sleep(1.5)
    webbrowser.open("http://localhost:8765")

def get_base_path():
    """取得資源路徑（PyInstaller 打包後的路径）"""
    if getattr(sys, 'frozen', False):
        return os.path.dirname(sys.executable)
    return os.path.dirname(os.path.abspath(__file__))

def main():
    base_path = get_base_path()

    # 確保 data 目錄存在
    data_dir = os.path.join(base_path, "data")
    os.makedirs(data_dir, exist_ok=True)

    # 設定 SQLite 路徑
    db_path = os.path.join(data_dir, "scheduler.db")
    os.environ["DB_PATH"] = db_path

    # 設定 static 目錄
    static_dir = os.path.join(base_path, "static")
    os.environ["STATIC_DIR"] = static_dir

    # 啟動瀏覽器
    threading.Thread(target=open_browser, daemon=True).start()

    # 啟動 FastAPI
    uvicorn.run("app.api:app", host="127.0.0.1", port=8765, log_level="info")

if __name__ == "__main__":
    main()

十八、關鍵實作注意事項
================================================================================

1. 班次銜接的跨月處理
   - 需將上月最後一天班次作為「day -1」加入銜接矩陣檢查
   - 連續上班天數需從上月最後 5 天開始累計

2. 每週休 2 天的跨月處理
   - 跨月週的休假計算需合併上月和本月的資料
   - 上月已休天數從 previous_month_links 或上月 schedule_entries 讀取

3. 連休 2 日判定
   - 特休會打斷連續判定（特休那天視為「非參與型」，重置連續計數）
   - 需實作掃描邏輯：逐日檢查是否為參與型休假，計算連續段數

4. D 班備援
   - 備援日 C+D 備援人員的班次固定為 D（不設決策變數）
   - 需確保當日 C 班至少有 1 人（排除該 C+D 備援人員）
   - 若無人可上 C 班 → 排班失敗

5. 大夜專職人員
   - 班次由手動輸入固定，不參與自動排班
   - 但需驗證其休假規則合規（H2/H3/H4/H12）
   - 大夜人員的班次也需納入跨月銜接檢查

6. OR-Tools 線性化
   - 軟性約束中的乘法項（如 x[e,d,B] * x[e,d+1,A]）需線性化
   - 使用輔助布林變數 + OnlyEnforceIf 技巧

7. SQLite 路徑
   - 打包後 DB 路徑需根據 sys.executable 動態計算
   - 確保 data/ 目錄與 .exe 同層

8. 前端即時驗證
   - 手動微調時需呼叫後端 /solve/validate API
   - 或前端實作輕量級規則檢查（即時回饋）

9. 月份天數處理
   - 使用 Python calendar.monthrange() 取得當月天數
   - 注意 2 月閏年

10. 時區
    - 系統為本地使用，不需處理時區轉換
    - 日期使用 datetime.date 即可

F. 排班引擎架構
================================================================================

F.1 決策變數
  x[emp_idx, day_idx, shift] ∈ {0,1}，shift ∈ ALL_SHIFTS
  統一建立所有格位的 BoolVar；固定格（大夜/指定休/特休/D備援）透過
  domain 限制 + H6/H7/H10/H11/H13 強制，而非省略變數。

F.2 硬性約束 H1~H13（constraints/hard.py）
  H1  每日覆蓋：A>=1, C>=1（M 不計入覆蓋）；A<=2,C<=2,B<=1,D<=1
  H2  每週休 2 天（週一為週首，跨月週 H9 處理）
  H3  週末限制（每月 Sat+Sun OFF 加總 =2；大夜 <=2）
  H4  連續上班 <=5（6 天視窗至少 1 休/特休，含跨月 5 個 spanning windows）
  H5  班次銜接禁止：C→A, D→A, D→C, D→M（D→M 為 Phase 7.5 新增）
  H6  指定休假固定 OFF
  H7  可用班次限制（只排 available_shifts ∪ OFF）
  H8  跨月銜接（上月末→本月首 H5 規則 + spanning H4 視窗）
  H9  跨月週休假合併（prev_off + curr_off == 2）
  H10 一天一班（sum == 1）
  H11 D 班備援（cd_backup 備援日固定 D + 當日 C 有人遞補）
  H12 連休 1~2 次（輔助布林變數線性化，按月歸屬）
  H13 大夜專職手動固定

  ★ 逐人規則開關（Phase 7.5）：H2/H3/H4/H9/H12 對大夜人員檢查
    _rule_enabled(data, emp, rule)；若該規則未在 night_rule_overrides 啟用集中，
    則跳過該人員該規則。無記錄時預設全部啟用（向後相容）。

F.3 軟性約束 S1~S3、S5~S10（constraints/soft.py，最大化目標函數）
  S1  避免 5 連續上班（-10）
  S2  B→A 避免（-5，含跨月）
  S3  C→B 避免（-5，含跨月）
  S5  偏好班次（+5，只對非固定格）
  S6  公平分配（max-min 上班天數差 × -3）
  S7  D 班備援最小化（cd_backup 非備援日 D × -2）
  S8  管理職備援最小化（manager 上 A/B/C/D × -15，Phase 7.5 新增）
      → 權重 -15 > S5 +5，確保管理職優先上 M；但覆蓋不足時 solver 仍會排備援
  S9  連休 2 次優先（每人連休次數 × +8，v1.0.3 新增）
  S10 週末人力加強（週五/六 雙A=雙C=M +6，平日B +3，v1.1.1-beta 調整）

  求解參數：max_time_in_seconds=30, num_search_workers=8,
            log_search_progress 由 env SCHEDULER_LOG_SEARCH_PROGRESS 控制（預設關）

F.4 validator.py（規則驗證器）
  - validate(data, schedule) → 結構化硬性違規 [{rule, employee_id, employee_name, day, message}]
  - validate_soft(data, schedule) → 軟性警告（S1~S3, S7, S8）
  - count_preferred_unsatisfied（S5）、compute_fairness_spread（S6）
  - RULE_DESCRIPTIONS（H1~H13 + S1~S3、S5~S8 共 20 條）
  - 用於：整月驗證報告、大夜驗證、cell 驗證、diagnostics

F.5 diagnostics.py（失敗診斷）
  diagnose_detailed(data) → {likely_causes, constraint_analysis}
  cause 類型：coverage_gap / over_capacity / d_backup_gap /
              cross_month_conflict / designated_over_limit / night_violation / unknown
  ★ over_capacity 判定：非大夜員工 > 8 人（H1 每日上限 6 工班×7=42，每人週 5 工天）

F.6 validate_cell（schedule_service，手動微調即時檢查）
  假設性檢查（不寫 DB）：H4（含該格 6 天視窗含跨月）/ H5（前後銜接含跨月）/
  H7 / H12（重算連休）+ S2/S3（前後銜接）。D→M 已包含。

     - support_requests 表，手動 + 排班失敗自動生成
  4. 抬頭可修改（settings 表 hotel_name，Header 點擊編輯）

H.2 命名衝突處理
  原規格 directory structure 同時有 app/api.py 與 app/api/ 套件 → Python 無法共存。
  實際將 FastAPI app 定義放在 app/api/__init__.py，main.py/run.py 用
  uvicorn.run("app.api:app") 或 from app.api import app。

H.3 solve meta 持久化
  原規格 solve 只回傳結果不存。實際將 objective_value/solve_time/soft_stats
  存於 settings 表（key solve:{y}:{m}），供統計報表讀取。
  seed_dev.py 直接呼叫 engine 不存 meta，故統計需透過 UI「一鍵排班」才完整。

H.4 連休計數語義
  count_consecutive_off 合併「指定休 + 特休 + 已排班 OFF」三來源；
  特休打斷連續判定；按月歸屬（跨月 split）。

H.5 PyInstaller 打包關鍵
  - run.py 須 `from app.api import app`（非字串 import）讓 PyInstaller 追蹤依賴
  - build_spec.py 用 --collect-all=ortools/fastapi/pydantic/sqlalchemy
  - --add-data=frontend/dist:frontend/dist（前端靜態檔）
  - frozen 模式 DB 路徑 = exe 同級 data/scheduler.db（config.py 處理）

J. 已知限制與注意事項

1. Python 版本：開發環境為 3.14.6（原規格 3.11）。OR-Tools 9.15 支援 3.14。

3. M 班無每日上限：H1 不限制 M 人數（管理職通常 0~1 人）。如多管理職需自行評估。

4. 跨平台打包：PyInstaller 不支援跨平台編譯。Linux 上 build_spec.py 產出 ELF，
   Windows .exe 需在 Windows 機器執行同一腳本。

5. 連休/連續上班的跨月處理：
   - H4 連續上班：載入上月最後 5 天（previous_month_links）一起算
   - H12 連休：按月歸屬（跨月 split，本月第一天重新起算）
   - previous_month_links 只存 5 天；若月初為週日（需 6 天）則最舊那天缺，
     以現有 5 天計算（少見邊界）

6. log_search_progress：預設關（避免污染 stdout），需觀察求解過程時設
   env SCHEDULER_LOG_SEARCH_PROGRESS=1。

7. 前端 build 後由後端 mount "/" 服務；開發時 vite proxy /api → 8765。
   API 路由註冊在 mount 之前，故 /api/* 優先匹配。

8. 大夜規則開關只影響 H2/H3/H4/H12（及 H9 跨月週）；H5/H8 銜接、H10 一天一班、
   H13 大夜固定等不受開關影響（始終強制）。

K.2 多館支援（Multi-Branch，2026-08-21 討論，未實作）
================================================================================

  動機:
    兩館共用 3 位專職大夜，大夜 D 班橫跨兩館。現行軟體只排單館 A/B/C/M，
    D 班由另一館負責人手動 key 入。若兩館都要用這套軟體排所有人的班，
    需處理「跨館共用大夜」與「各館獨立排班」。

  核心洞察:
    D 班是唯一跨館耦合點；兩館的 A/B/C/M 班彼此獨立、互不影響。

  流程（沿用現行人工流程，自動化大夜）:
    1. 3 位大夜劃定指定休假 → 大夜 solver 排兩館每日各 1 個 D（60 槽/月）
    2. 排不滿的日子自動產生 d_backup_requests（標記哪館哪天缺 D）
    3. 各館 solver 以「共用 D 班表」為固定輸入 + 備援需求，各自獨立排 A/B/C/M

  資料模型增量（加欄位、向後相容）:
    branches          (id, name)
    users             (id, username, role, branch_id)   role: admin/night/branch
    employees         + branch_id（NULL = 大夜共用池）
    schedule_entries  + branch_id（大夜的 D 標記哪館哪天）
    d_backup_requests + branch_id

  角色與權限:
    admin    Josh          全館全功能
    night    大夜排班人員   只排大夜池（D + 備援需求）
    branch   各館排班人員   只看/改自己館 A/B/C/M + 唯讀看共用 D 班表

  模式切換:
    單一 APP_MODE = single | multi：
      single（預設，現況）: 無登入、無館維度、D 手動，行為與現在一致
      multi: 登入 + 館切換 + 大夜 solver + 角色權限

  登入:
    採 Cloudflare Access 擋門（沿用既有 Cloudflare Tunnel），app 內不自建帳密系統。

L.1 瀏覽器關閉偵測 → 自動關閉後台（v1.0.2）
   動機:
     原本 browser-based 架構下，使用者關閉瀏覽器分頁後，後端 process 仍在背景
     執行，不熟電腦的使用者難以理解「如何完全關閉程式」。

   實作方式（候選方案一 + 選項四，雙訊號互補）:
     1. 前端 heartbeat（心跳）
        - 每 5 秒 fetch GET /api/v1/lifecycle/heartbeat 當心跳
        - focus / visibilitychange(visible) 補送，降低背景節流誤判
     2. 關閉訊號（beacon，主訊號）
        - window 'pagehide' / 'beforeunload' 中 navigator.sendBeacon
          POST /api/v1/lifecycle/shutdown-signal → 延遲 3 秒關閉
     3. 後端 LifecycleManager（backend/app/lifecycle.py）
        - 記憶體記錄 last_heartbeat（不持久化）
        - 背景 thread 每 5 秒檢查：超過 90 秒無心跳 → 優雅停止 uvicorn
        - beacon 觸發 → 3 秒延遲關閉；期間恢復心跳則取消（避開 refresh 誤關）
        - UI 按鈕 POST /lifecycle/shutdown → 1 秒延遲關閉
     4. 容錯
        - refresh：pagehide 觸發 beacon → 新頁 heartbeat 於延遲內取消
        - 當機/強制關閉瀏覽器：心跳超時 90 秒兜底
        - 背景分頁節流：90 秒長超時避免誤關（正常關閉靠 beacon 即時）

   開發模式保護:
     - lifecycle 僅由 run.py 呼叫 enable() 才生效
     - uvicorn app.api:app（開發）未 enable → 所有訊號 no-op，不會誤關

   備選方案（未實作，供未來參考）:
     選項二 pywebview 原生視窗：關閉視窗即結束（最像桌面軟體，但需 WebView2
            Runtime + 打包重測，工時較高）
     選項三 系統匣圖示（Tray）：右鍵選單「開啟瀏覽器 / 離開」，需 pystray/Pillow

L.3 班表狀態與版本管理（Status & Version Management，v1.0.3）
================================================================================

  優先順序：狀態鎖定 > 版本快照還原 > 變更日誌

L.3.1 班表狀態生命週期（Status Lifecycle）
  每月的排班表有三種狀態（儲存於 schedule_statuses 表）：

  🟡 草稿中（Draft，預設）：
    自由排班階段，可隨意「一鍵排班」、手動微調格位。

  🟢 已發布（Published）：
    排班確認後點擊「發布班表」進入此狀態。
    防誤觸機制：
      - 「開始排班」按鈕受保護（點擊跳出強制警告確認，避免覆蓋已發布班表）
      - 手動修改格位：跳出確認對話框
        （例：「目前班表已發布，確定要將 王先生 8/15 班次由 A 改為 C 嗎？」）

  🔒 已鎖定 / 封存（Locked）：
    適用過往結算月份，完全唯讀，禁止格位修改與重排
    （需修改必須由主管解鎖為 Draft 或 Published）。

L.3.2 版本快照與還原（Version Snapshots & Restore）
  快照儲存（schedule_snapshots 表）：
    欄位：id, year, month, version_number(v1, v2...), name(版本名稱/備註),
          schedule_data(完整班表格位與請假狀態 JSON), created_at

  觸發時機：
    自動：每次「一鍵排班成功儲存」自動建立（例：v1 - 自動排班結果）；
          點擊「發布班表」自動建立（例：v2 - 正式發布版）
    手動：UI「建立目前快照」按鈕，主管可自訂名稱（如「調整大夜前備份」）

  版本歷史面板（Version Drawer）：
    - 點擊班表頂部「版本歷史」按鈕展開，瀏覽該月快照清單與時間軸
    - 「一鍵還原至此版本」：確認後將當前班表覆寫還原為該快照
    - 「版本比對（Diff View）」：勾選兩版本比對差異，高亮誰在何日班次變動

L.3.3 發布後變更日誌（Change Log）
  Published 狀態下手動微調時：
    - 微調確認視窗可填寫「調班原因（選填：與同仁換班、臨時請病假）」
    - 自動寫入 schedule_change_logs 表

    - 班表頁與統計頁提供「調班紀錄」抽屜/分頁，供調閱與匯出

L.5 D 班備援指派鏈（D Backup Assignment Chain，v1.0.6）
================================================================================

  動機:
    現行 D 班備援日只固定挑第一個 CD 備援人員；沒有 CD 備援或該員當日請假時，
    指示形同失效（不排 D、也不提示）。

  指派優先鏈（求解前自動指派）:
    CD 備援（當日無指定休假/特休等請假者） → 管理職 → 無法指派。

  實作細節:
    - 指派由 data_loader 載入時決定（尊重 DB 既有 assigned_employee_id），
      未指派者走優先鏈；無法指派者記入 d_backup_unfillable。
    - night 端點回傳指派對象（姓名/角色/是否無法指派/原因）供 UI 顯示。
    - 管理職補 D 時，班表 source 標記為 "backup"。
    - 求解前引擎偵測 d_backup_unfillable 即回傳失敗，不進入求解。

L.6 當月臨時異動（Temporary Adjustment，v1.0.7）
================================================================================

  動機:
    月份已排班（甚至已發布）後，員工可能突發請假（如 8/20 得知 8/21-8/23 需請假），
    需要以「影響最小」的方式局部重排，而不是整月重算。

  目標（最少受影響人數 > 最少變動格數）:
    1. 凍結過去日期（今天以前）不動。
    2. 請假日固定為 SPECIAL（寫入 SpecialLeave，統計照算）。
    3. 以現有班表為底重排：優先減少受影響人數，其次減少變動格數；
       不使用原本 S1-S9 偏好（避免為了優化多改）。

  流程:
    選員工＋日期範圍＋假別 → 預覽 diff（dry-run）→ 確認套用。
    套用時逐格寫入並記錄 change log（已發布月份）。

  實作細節:
    - engine.solve_adjust：凍結過去 + 新請假，Minimize(sum(受影響人)*BIG + sum(變動格))。
    - adjust_service：preview（in-memory 注入請假、不解 DB）與 apply（逐格 upsert_cell）。
    - API：POST /schedules/adjust/preview、POST /schedules/adjust/apply。
    - 排班畫面預設顯示「下一個月」（當月通常已排班發布）。

L.7 週末人力加強（S10，v1.1.0-beta；v1.1.1-beta 調整）
================================================================================

  動機:
    週六、週日客人較多，現行排班只保證每天 A≥1、C≥1，週末人力可能不足。
